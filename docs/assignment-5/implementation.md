# Implementation status and known limitations

**Verified deployment, November 27, 2026.** The Windows application opened in Edge, captured ambient Ethernet traffic over two start/stop sessions and replayed deterministic fixtures through the actual dashboard. Firefox also displayed the replayed records. The application opens directly to monitoring. Local administrator protection applies to selected modifications. | SE Document use case | Running implementation and verification boundary |
|---|---|
| UC1 Packet Capture Session | Npcap delivers records to the native worker. Ethernet-format frames are decoded into packet metadata. The C++ filter combines enabled criteria with AND. Session statistics include frames hidden by display filters. Unsupported link formats and truncated headers have explicit outcomes. |
| UC2 Packet Export | The browser downloads all, filtered or selected packet metadata as CSV/JSON. Imported metadata appears in a separate paginated view. The application reads pcap for replay. It has no raw capture-file writer. |
| UC3 Subnet Discovery | Windows adapter information, OS neighbor entries and local packet evidence support passive inventory. PTR and passive naming can supply hostnames. Local evidence and remote observed endpoints have separate views. Active subnet sweep and ping timing remain unavailable. |
| UC4 Device Labeling | Labels and trust preferences attach to an identity scoped by MAC, adapter and network context. Restart persistence was verified with a temporary store. Randomized MACs can appear as new identities. |
| UC5 Per-device Bandwidth | The live graph shows an aggregate rolling rate from original wire lengths. The analyzer sample verifies directional pair totals. Live per-device bandwidth/download rates are incomplete. |
| UC6 Daily History Export | Packet history can be exported. The live system lacks a persisted daily-usage series to export. |
| UC7 Unauthorized-device Alerts | The initial baseline is quiet. Subsequent untrusted arrivals, alternating ARP claims, confirmed gateway changes and sustained packet-rate spikes can generate evidence-bearing advisories. Replay fixtures demonstrate evidence and acknowledgment. A device's trust flag expresses operator preference. |
| UC8 Custom Bandwidth Thresholds | Authorized users can adjust a sustained frames/s threshold and rule switches. A bandwidth threshold in Mbps remains an open requirement. |
| UC9 Dashboard Monitoring | React renders telemetry obtained through the local WebSocket. The graph, counters, recent retained packets and alert previews share the live workspace. The connections KPI estimates recently observed bidirectional transport flows. |
| UC10 Session Control | The shared controller starts and stops the worker and reconnects after bridge interruption. Metadata survives start/stop and page reload while the bridge lives. A bridge restart ends the packet-history lifetime. |
| UC11 Log Cleanup | The live UI can clear packet history while paused and purge security events after confirmation and required authorization. Imported logs are separate. Archive-size labels in legacy tests do not describe disk reclamation in the live application. |
| UC12 Configuration Startup | Saved live monitor preferences and local credentials reopen on startup. A separate tested frontend parser accepts a supplied JSON string. A general user-selected startup configuration file is not wired into the launcher. |

**Data path.** The worker owns the pcap handle and checks its link type before parsing. Its bounded detail mailbox defaults to 256 rows. Worker counters include frames whose display details overflow. The bridge retains up to 4,096 packet rows across sessions, carries rates between active intervals, and serves the React workspace. A slow controller can disconnect. Discovery and alert rules that need packet details can miss observations lost before the bridge. Live device preferences and up to 512 security events persist separately. Replay uses in-memory monitoring state. [Service contracts](../../backend/service/README.md) · [Worker and bridge measurements](nonfunctional.md)

**FR25.** A chosen local setup file proves first-time enrollment access. The bridge verifies the proof and persists a salted scrypt verifier. Locking, inactivity, password changes, connection loss and restart invalidate access under the tested session rules. Rule changes, active reverse-DNS settings, device trust and labels, capture-history clearing and security-log purging require backend authorization when enrolled. Capture, inspection, filtering, reading and acknowledging alerts remain accessible. The client renders challenges and resumes an authorized action. **Outstanding verification and defects.** Application detail losses were material at the default queue setting, including during ambient capture. Driver loss remains unknown. Multi-hour memory stability, physical adapter removal, Linux deployment, arbitrary operating environments and long-term credential file ACL administration have not been certified. Device names depend on observed data or a successful lookup. New-device rules cannot prove network admission.
