# Non-functional test plan and results

The test host ran Windows 11 Pro 25H2 build 26200.9974 on an i7-8700 with 12 logical CPUs and 31.95 GiB RAM. The capture worker was a GCC 16.2 Debug build using Npcap 1.90 and the Intel I219-V Ethernet adapter. The library-only build was Release. The measurements below came from November 27, 2026. Commands and tool versions accompany the [run index](README.md) and [environment record](evidence/environment.txt).

**Disposition.** Eight scoped passes, four Not Run (02, 06, 08, 10), one Blocked (07), zero NFRs classified Fail under the stated procedures. The loss finding below separately fails the operator-visible, end-to-end zero-loss criterion. The passing latency rows describe records that reached the measured boundary.

## Throughput and loss finding for FR27

| Workload with 256-record output queue | Elapsed | Parsed / rejected | Output drops | Delivered detail | Parse rate |
|---|---:|---:|---:|---:|---:|
| Ambient Ethernet, PowerShell reader | 180.273 s | 47,680 / 0 | 12,066 (25.31%) | 35,614 inferred from final counters | 264.49/s |
| Ambient Ethernet, Node reader | 60.035 s | 25,363 / 0 | 16,272 (64.16%) | 9,091 counted | 422.47/s |
| Deterministic 30,000-frame burst, Node reader | 0.588 s | 30,000 / 0 | 29,232 (97.44%) | 768 counted | 51,054.97/s |

The worker processed 25,751,640 wire bytes in the first run and 19,365,880 in the second. Working counters can advance while packet details are discarded from the bounded mailbox. The live workloads were uncontrolled, so these runs cannot isolate a reader or driver effect. Raw traffic was not retained. Neither the number of frames offered on the wire nor driver loss via `pcap_stats` was available. This evidence establishes application output loss and leaves wire-level capture completeness unverified.
