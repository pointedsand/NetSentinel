# NetSentinel v0.1.0-demo

Windows x64 demonstration pre-release for the November 30 university presentation.

Installer SHA-256: `d580c279787fa6226ffcbe9deef9a904eb797e42f338adf9798715becbfc2e82` (122,030,540 bytes).

- Install the [Npcap runtime](https://npcap.com/#download) separately, then run **NetSentinel-0.1.0-demo-windows-x64-setup.exe**. The demo installer is unsigned. The package contains the React production interface, Electron runtime, local bridge and native capture worker.
- Open **NetSentinel** from Start, select an authorized Ethernet-format capture adapter and click **Start capture**. Open Packets to filter or inspect the results. The bundled `--demo` mode replays three synthetic frames and one device-arrival advisory.
- The desktop app reuses the existing local credentials, device labels, trust, rules and security history for the Windows account. The sandboxed renderer uses the same backend authorization and setup-file enrollment as the browser deployment.
- Windows x64 is the tested desktop target. Linux packaging and live Linux compatibility remain unverified. Raw Wi-Fi decoding, active subnet scanning, daily per-device usage and automatic archive compression remain incomplete.
- At the default 256-record buffer size, the Assignment 5 Windows baseline parsed 47,680 frames in 180.273 seconds and discarded 12,066 packet-detail records (25.31%). The counter continues to advance when detail output overflows. Driver-level loss is unknown. [Measurement procedure and results](https://github.com/pointedsand/NetSentinel/blob/v0.1.0-demo/docs/assignment-5/nonfunctional.md)

The source tree and build instructions accompany the tag. Electron and Chromium licenses ship alongside the application.
